Tapboard+ 타이핑 실험실

실행
저장소 최상위의 tapboard-test.html을 Chrome 또는 Edge에서 열면 인터넷 없이 실행됩니다.
이 HTML 한 파일만 USB 등으로 다른 PC에 옮겨도 실행됩니다. 로그인이나 빌드 도구는 필요 없습니다.
분리된 소스로 실행하려면 dist 폴더 전체를 복사하고 dist/index.html을 여세요.
같은 주소와 브라우저를 유지해야 이전 기록이 보입니다.
자유 연습은 페이지를 열고 바로 타이핑하세요. 기본 영어·한국어 세트에서는 Enter로 다음 문장으로 넘어갑니다. 문장을 정확히 다 치고 끝에서 스페이스바를 눌러도 넘어갑니다.
로깅 시작을 누르면 빈 줄에서 새 회차를 시작하며, 이때부터의 입력만 기록됩니다.

다른 컴퓨터에서 Git으로 받기
처음 받을 때:
  git clone https://github.com/sungjaep11/tapboard.git
  cd tapboard
이미 받은 저장소를 업데이트할 때:
  git pull
그다음 최상위 tapboard-test.html을 Chrome 또는 Edge에서 여세요.
tapboard-study는 일반 폴더로 함께 내려받습니다. submodule 명령은 필요 없습니다.
새 변경 사항은 작성한 컴퓨터에서 먼저 commit과 push를 해야 다른 컴퓨터에서 받을 수 있습니다.

Windows Tapboard 앱
실제 터치 로그를 연결하려면 dist/downloads/Tapboard-touch-experiment-v1.1.zip을
압축 해제하고 안의 안내에 따라 TapBoard.exe와 설정 파일을 함께 사용하세요.
브라우저에서 기본 타이핑 측정만 할 때는 별도 앱 설치가 필요 없습니다.
기존 컴퓨터의 실험 기록은 Git에 포함되지 않습니다. 이전 기록은 CSV/JSON으로 따로 보관하세요.

소스 수정 후 단일 HTML 갱신 (개발용)
저장소 최상위에서:
  python3 tapboard-study/build-standalone.py
Windows에서는 Python이 설치되어 있을 때:
  py -3 tapboard-study/build-standalone.py
실험만 실행하는 컴퓨터에는 Python이나 Node.js가 필요 없습니다.

문단 입력 및 두 지도 (v1.2)
1. 최신 저장소의 tapboard-test.html을 위쪽 화면에서 엽니다. 기본 과제는 ‘문단 입력 · 홈키 및 탐색 지도’입니다.
   영어 목표 문장을 한 줄에 하나씩 넣습니다. 한 회차가 한 문단입니다.
2. 아래쪽 디스플레이의 실제 표시 영역 가로 길이(mm)와 키 중심 간격을 입력합니다.
   A/B 기본 실행 방식은 Windows ConvBoard 앱입니다. ConvBoard-Windows.zip 압축을 풀고 TapBoard를 닫은 뒤
   ConvBoard.exe를 실행합니다. 페이지에서 문서/TapBoard-Experiments의 최신 convboard-touch-*.jsonl을 연결합니다.
   키보드의 실제 화면 가로 해상도와 키 간격(px)은 로그에서 자동으로 읽습니다. ConvBoard.exe.config의
   DisplayWidthMm과 KeyPitchMm을 TapBoard 설정과 맞추세요. 이전 브라우저 방식은 ‘브라우저 키보드 창’에서 선택할 수 있습니다.
   C/D에서는 Windows TapBoard를 실행하고 최신 JSONL을 연결합니다. 아래 화면의 실제 가로 해상도(px)를 입력합니다.
   앱의 DisplayWidthMm과 KeyPitchMm이 연구 페이지 값과 같아야 키 사각형과 mm 위치가 일치합니다.
   가로 보정은 정사각형 픽셀을 가정합니다. 장치에서 필름의 F·J 중심과 화면 키 중심 정렬을 확인합니다.
3. 참가자, 조건(A/B/C/D), 블록과 연습/본 실험을 지정하고 시작합니다. 화면에 손을 뗀 상태가 확인된 뒤
   홈키 신호가 나타납니다. 참가자는 두 검지만 놓고, 화면 지시에 따라 제자리에서 듭니다. 먼저 닿은
   두 점의 x좌표로 좌우를 배정합니다. 키를 빗나가도 그대로 기록합니다.
4. Enter로 문장을 제출합니다. 다음 문장 전 양 검지를 올려 정확히 두 접촉을 연속 3초 유지합니다.
   어느 하나라도 떨어지거나 다른 접촉이 추가되면 다시 셉니다. 신호가 나타나면 검지를 들고 타이핑합니다.
   마지막 Enter로 문단이 종료됩니다. 터치 연결이 끊기면 중단 버튼으로 원자료를 저장합니다.
5. ‘홈키와 탐색 지도’에서 조건과 연습/본 실험을 선택합니다. 완전히 수집된 완료 문단만 합산합니다.
   홈키 지도에 각 검지의 최초 접촉을 표시합니다. 탐색 지도에는 하나의 문장 입력 구간 안에서
   down부터 up까지 완결된 접촉 중 400ms 초과, 누적 이동거리 1.9mm 초과인 경로를 표시합니다.
   고정한 손이나 강제 레스팅 중 움직임은 탐색 궤적에 포함되지 않습니다. 두 지도는 각각 PNG로 저장할 수 있습니다.
6. 전체 JSON에는 키 배치 및 보정값, 단계별 시각, 조건, 문장별 목표/입력/반응시간/WPM, 홈키 접촉,
   원시 좌표와 탐색별 접촉 ID·원시 이벤트 순번·시간·거리·문장 내 시간 10분위가 포함됩니다.
   ‘전체 JSON에서 지도 열기’로 내보낸 회차의 그림을 다시 볼 수 있습니다. 요약 CSV만으로는 재현할 수 없습니다.
   문단 WPM은 문장별 (문자 수−1)의 합을 문장별 입력 시간 합으로 나눠 계산합니다. 최초 입력 지연과
   문장 사이 강제 레스팅은 제외합니다. 문장별 입력 시간이 0이면 그 문장은 속도 계산에서 제외합니다.
   아래 ‘단일 문장’ 흐름과 측정 정의는 기존 과제에 적용됩니다.

단일 문장 로깅 순서
1. 상단 화면에 이 페이지, 하단 화면에 Tapboard를 엽니다.
2. 참가자 ID, 키보드 조건, 블록, 연습/본 실험을 지정합니다.
3. 프롬프트와 시작 전 레스팅 시간, 무입력 기준을 설정합니다.
4. 로깅 시작을 누르고 레스팅을 합니다. 입력 신호 후 프롬프트 바로 아래에 타이핑합니다.
5. 필요하면 레스팅/입력 재개를 사용하고, 문장 입력 후 회차 완료를 누릅니다.
6. 다른 문장 버튼으로 다음 문장을 선택합니다. 문장은 자동 변경되지 않습니다.
7. 요약 CSV, 이벤트 CSV, 전체 JSON을 내보냅니다.

기록
참가자/조건/블록/연습 여부/프롬프트/입력/메모, UTC 시작 및 종료 시각,
기록 시작 및 입력 신호부터 첫 키까지의 지연, 입력 신호부터 첫 확정 문자 지연,
WPM/CPM, 전체 문장 편집 거리 및 정확도, 삽입/삭제 문자, Backspace/Delete,
KSPC, 키 누름/해제, 반복 키, 평균 키 간격/누름 시간, 레스팅 구간,
무입력 구간, 포커스 이탈, 탭 숨김, IME 조합 이벤트 및 입력 전후 텍스트.
실행 중 내보내기도 가능하며 status=running으로 기록됩니다.

측정 정의
- 모든 상대 시간은 performance.now 기반 ms. UTC는 회차 시작 시각에 상대 시간을 더합니다.
- WPM = max(0,최종 NFC 문자 수 - 1) / 5 / (첫 삽입부터 마지막 확정 편집까지의 분).
  중간 레스팅은 WPM 분모에 포함됩니다. 첫 입력 대기와 완료 버튼을 누르기까지의 지연은 제외됩니다.
  단 한 번의 입력이나 입력 없음은 WPM=null입니다. 한글은 음절 수 기준이므로 언어 간 WPM을 직접 비교하지 마세요.
- 정확도 = 100 * (1 - Levenshtein(전체 프롬프트,입력) / 두 문자열의 최대 길이).
  빠진 뒷부분도 오류에 포함됩니다. 미완성 입력에서도 같은 기준입니다.
- 수정으로 삭제한 문자 수는 실제로 수정한 오류 수가 아닙니다. 원시 텍스트 변경으로 추가 분석할 수 있습니다.
- 무입력 시간은 입력 신호부터 종료까지의 키 이벤트 간격 중 지시된 레스팅을 뺀 뒤,
  기준 이상인 각 구간의 전체 길이를 합산합니다. 손의 물리적 접촉 여부를 뜻하지 않습니다.
- 키 누름 시간은 브라우저가 받은 keydown/keyup 사이입니다. Tapboard의 SendInput 출력 특성 때문에
  손가락 접촉 시간과 다릅니다. 키 간격에는 레스팅을 포함합니다.
- 첫 키는 문자, 편집 키, IME Process 등 입력 관련 키 기준입니다. Shift/Ctrl만 누른 경우는 제외합니다.
- 한글 조합 중간 단계는 이벤트로 남기고, 확정된 텍스트만 문자 삽입/삭제 집계에 사용합니다.
- 실제 손가락 레스팅 시간, 터치 좌표, 거부된 탭, 잠금 상태, 접촉부터 키 출력까지의 지연은
  자동 연결 기능의 범위와 해석은 아래 내용을 확인하세요. 접촉-출력 지연은 원시 이벤트로 별도 분석해야 합니다.
- 기본 영어 세트는 MacKenzie & Soukoreff (2003)의 500문장을 순서대로 사용합니다. 한국어 세트는 자체 예시 문장입니다.

보관 및 복구
기록은 서버로 보내지 않고 해당 브라우저의 IndexedDB에 보관합니다.
약 1초마다 체크포인트를 저장합니다. 강제 종료 시 마지막 약 1초와 조합 중 문자가 손실될 수 있습니다.
진행 중 새로고침/종료는 마지막 저장 시점까지 복구하여 interrupted 상태로 남깁니다.
비공개 모드 종료, 브라우저 데이터 삭제, 저장공간 부족으로 기록이 사라질 수 있으므로
실험 종료 후 반드시 파일로 내보내세요. 저장 실패 시 알림이 표시되며 파일 내보내기는 유지됩니다.
JSON이 전체 데이터 원본입니다. CSV는 Excel 수식 실행 방지를 위해 =,+,-,@ 등으로 시작하는
문자열 앞에 작은따옴표를 추가할 수 있습니다. 원문은 JSON에 보존됩니다.

node --test tests/metrics.test.cjs

v1.1 터치 로그 자동 연결
1. 새 빌드의 TapBoard.exe와 TapBoard.exe.config를 함께 Windows PC에서 실행합니다.
   기존 실행 파일은 실험용 JSONL 로그를 만들지 않으므로 반드시 새 실행 파일을 사용하세요.
2. 같은 PC의 Chrome 또는 Edge에서 실험 페이지/오프라인 HTML을 엽니다.
3. 터치 로그 연결을 누르고 문서 폴더의 TapBoard-Experiments 안에서 최신 touch-*.jsonl을 선택합니다.
   앱을 실행할 때마다 새 파일이 만들어집니다. 기존 touch-diagnostics.csv는 실험 연동용이 아닙니다.
4. 실시간 연결됨을 확인합니다. 터치 기반 자동 측정이 켜지고, 로깅 시작부터 회차별로 자동 기록합니다.
   측정 도중 레스팅 버튼을 누르지 않아도 실제 터치 상태로 실측 레스팅이 계산됩니다.
5. 앱 재실행/페이지 새로고침 후에는 파일을 다시 연결하세요. 잘못된 파일/오래된 파일은 시작을 막습니다.

실측 정의
- 앱이 받은 NATIVE_DOWN/UP/MOVE에서 접촉 ID별 구간을 복원합니다. 기기 드라이버가 전달하지 않은
  손 접촉은 측정할 수 없습니다. 손가락인지 손바닥인지, 휴식 의도인지 이동 동작인지는 판단하지 않습니다.
- 기본 300ms를 넘긴 접촉의 초과 부분을 레스팅으로 셉니다. 예: 2초 접촉 = 1.7초 레스팅.
  기준은 웹페이지에서 50~10000ms로 지정할 수 있으며 회차 시작 시 고정됩니다.
- TAPPER 키와 빈 영역(BLANK)을 포함하고 MODIFIER 및 NORMAL(반복 키) 홀드는 제외합니다.
- physical_rest_ms는 여러 접촉 구간의 합집합입니다. 두 손가락을 동시에 2초 올려두면 3.4초가 아닌
  1.7초입니다. 손가락별 합계는 physical_rest_finger_ms로 따로 제공합니다.
- 회차 이전부터 유지된 접촉은 시작 지점에서 자르고, 종료 시에도 유지 중이면 회차 종료 지점에서 자릅니다.
- 지시된 레스팅(instructed_rest_ms), 무입력(idle_ms), 실측 레스팅(physical_rest_ms)은 각각 다른 지표입니다.
- raw JSON에는 touch.sessionId, touch.seed(시작 전 접촉), touch.events, native_t, utc, 상대 t,
  임계값과 시각 정렬 방식이 보존됩니다. 이벤트 CSV도 source=browser/touch로 구분해 포함합니다.

수집 상태 및 시간 기준
- Windows 앱은 입력 스레드에서 시간을 찍고 백그라운드에서 약 100ms마다 파일에 씁니다.
  페이지는 약 250ms마다 파일의 새 부분을 읽습니다. 이 주기는 화면 갱신 지연이며 접촉 시간 계산에는
  파일을 읽은 시간이 아니라 앱이 기록한 원래 타임스탬프를 사용합니다.
- 두 프로그램은 같은 PC의 UTC 시작 시각과 단조 증가 시계를 사용합니다. 이는 하드웨어 동기화가 아니며
  서로 다른 PC의 로그 또는 PC 시계 조정이 있으면 정밀한 비교가 불가능합니다.
- 앱 입력 스레드의 100ms 하트비트로 수집 가능 범위를 확인합니다. 1.5초 이상 하트비트가 비거나,
  접촉 ID 불일치/리셋/이벤트 손실이 생기면 그 지점 이후를 보수적으로 제외합니다.
- 회차 완료 시 마지막 하트비트를 최대 1.8초 기다려 종료 시점까지의 터치 이벤트를 반영합니다.
- touch_quality=complete/partial/not_connected 및 touch_coverage_ms/pct를 확인하세요.
  partial의 실측 값은 확인된 구간만의 합계입니다. 미연결은 0이 아니라 null입니다.
- 페이지가 새로고침되면 체크포인트에 저장된 터치 데이터로 복구되며, 마지막 파일 읽기 이후 데이터는
  자동 재연결하지 않습니다. 원본 JSONL은 Windows 문서 폴더에 남아 후속 분석에 사용할 수 있습니다.
- 앱이 켜진 동안 실험용 터치 로그가 계속 쌓입니다. 필요 없을 때 TapBoard.exe.config의
  ExperimentLogging을 false로 바꾸고 앱을 다시 시작하면 중단됩니다.
- 파일 한 개가 128MB를 넘으면 자동 읽기를 중단하므로 앱을 재시작하고 새 파일을 연결하세요.

지원되지 않는 브라우저에서는 안내가 표시됩니다. 사이트(HTTPS)에서의 실행을 권장합니다.
